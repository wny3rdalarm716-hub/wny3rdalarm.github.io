# Publishing reviewed public incident summaries

`reviewed-incidents.json` is a **public file**. Anything committed to it may be visible to anyone, including in Git history. Never copy raw dispatch feeds, notes, addresses, names, medical information, identifiers, or other sensitive material into the repository, a pull request, a commit, logs, or the helper. The app does not read the automated Active911 feed.

1. A designated publisher privately reviews the source and independently decides whether a general fire category is appropriate for public release after the incident is concluded. Never publish active scene locations or ongoing response details. Do not publish medical calls, precise locations, or unreviewed dispatch notes.
2. On a trusted local checkout, run `python3 app/publish-reviewed.py`. Select an allowed category and explicitly confirm `REVIEWED`. The tool accepts no free-form incident text or locations. It creates only a fixed category, a review marker, and the **UTC review hour**, not an incident time; old records are removed. The app labels the timestamp as the review time and displays only records from the last 24 hours. Cancel or stop if unsure.
3. Inspect the complete JSON diff and submit it on a branch in a pull request. A second authorized reviewer must verify each record against the private source and approve the PR. Do not put that source, confidential notes, or sensitive explanations in the PR. Only then merge and publish via your existing deployment process. If a record is unsafe, do not merge it; remove it before publishing. Consider Git history public once pushed.

**Access control is essential:** a `reviewed: true` field is an assertion, not proof of review. Configure repository permissions and branch protection/rulesets to require an independent approval before changes to the published branch can merge, limit bypass rights, and restrict who can deploy. This static site and helper cannot enforce those GitHub controls or authenticate reviewers. Never let automation mark an item reviewed. The helper rejects unexpected fields in an existing file; the app additionally restricts output to an allowlist and a fixed region, but client-side filtering cannot protect content placed in a public JSON file.
